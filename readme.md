# Описание сервиса

Данный сервис занимается оценкой стоимости автомобилей с веб-ресурса avito.ru. Непосредственной оценкой будут заниматься несколько LLM с разными ролями. Общий алгоритм выглядит следующим образом:
- авторизованный пользователь передает на вход сервиса ссылку на объявление;
- сервис парсит объявление, с помощью отдельной модели анализируются данные из фотографий машины и формирует контекст для оценки; У авито есть защита от веб-скреппинга, поэтому данные будет готовить пользователь, в противном случае стабильно система работать не будет; 
- далее на основе полученной информации 2 разные LLM начинают спор о том, какая должна быть стоимость автомобиля. Первая роль пытается снижать стоимость придираясь ко всему, что угодно, а вторая пытается увеличивать стоимость рассматривая только положительные аспекты автомобиля;
- эти LLM спорят ограниченное количество раундов;
- после того, как спор закончился, третий LLM - координатор анализирует их аргументы и формирует окончательную оценку стоимости автомобиля и рекомендации для пользователя;
- после окончания оценки пользователь получает эту информацию;
- при этом у пользователя уменьшается баланс на определенное количество кредитов, в зависимости от сложности оценки.


# Функциональные требования к личному кабинету

- Главная страница с описанием возможностей ML сервиса
- Возможность зарегистрироваться и авторизоваться
- Возможность просматривать баланс (баланс в условных кредитах)
- Возможность пополнять баланс через кнопку пополнить (эквайринг подключать не требуется)
- Возможность выполнить запрос к ML сервису из Web интерфейса со списанием кредитов с баланса (при условии успешного выполнения запроса)
- Возможность просматривать историю загруженных данных и предсказаний по ним, с указанием суммы списанных кредитов
- Возможность выполнять запросы к ML сервису с помощью REST интерфейса
- Требуется предусмотреть валидацию данных. Если в загружаемой выборке присутствуют ошибочные данные, то возвращать их пользователю, а над валидными данными производить предсказание
- Требуется предусмотреть проверку на положительный баланс при запросах к системе.
- Роль администратор подразумевает возможность пополнять баланс пользователям (модерировать пополнения от пользователей) и просматривать все транзакции.
